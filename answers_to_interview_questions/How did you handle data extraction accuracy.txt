  What's actually in the code today (you built this)

  Point the interviewer to scripts/scholarshipDB.ts:286-369 (validateScholarship) — it's the most defensible part:

  1. Prompt engineering guardrails (buildScrapePrompt, scripts/scholarshipDB.ts:230-284):
    - Returns JSON-only with an exact top-level shape spelled out.
    - Explicitly forbids inventing values ("when uncertain, use concise fallback text").
    - Preserves original markdown formatting rather than summarizing.
    - Includes an exclusion list of already-known scholarship names so re-runs don't re-extract duplicates.
  2. Hard-required fields — missing name, organization, description, or link → rejected outright.
  3. Link sanity check — isSameUrl(link, source.url) rejects entries whose "link" is just the source listing page rather than a scholarship detail page.
  This was a real failure mode I hit.
  4. Vagueness threshold — counts how many of country / funding / field / academicRequirements / description match a placeholder list ("See source", "Not
  specified", "Unknown", "General", empty). If 3 or more are vague, the row is rejected as a likely "trash link." This is the piece I'm most proud of
  because it's the realistic failure mode for LLM scraping — the model produces a shaped JSON object but half the fields are stubs.
  5. Normalization — normalizeCountry and normalizeDegreeLevel map free-text LLM output to a controlled vocabulary, so "U.S.", "USA", and "united states"
  all land in the same bucket.
  6. Dedup + idempotent upsert — slugified id + onConflict: 'id' means the same scholarship extracted twice just gets updated, not duplicated.

  What I'd build with unlimited time — two prongs

  Prong 1 — Reach (handle DAAD-class sites):

  - Headless browser layer (Playwright or Puppeteer) for sites that need clicks, scrolls, or waits. Run it as a separate worker service that produces a
  snapshot HTML, then feed that HTML to the LLM extractor. Keeps extraction model-agnostic.
  - Site-specific adapters for the top 5-10 high-value sources (DAAD, Chevening, Fulbright, MEXT). Generic LLM extraction is great for the long tail;
  hand-written selectors win on the head for both accuracy and cost.
  - Provider fallback that actually falls back — today SCRAPE_PROVIDER is an either/or switch; I'd chain Interfaze → OpenAI web-search → Playwright scrape
  so the pipeline degrades gracefully instead of skipping a source entirely.

  Prong 2 — Extraction quality (measure it, don't just hope):

  - JSON-Schema structured outputs on the scrape call. The chat and evaluate routes already use OpenAI's strict json_schema format; the scraper path still
  parses free-form JSON and strips markdown fences. Upgrading it means zero malformed-output retries.
  - Golden eval set — 30-50 hand-verified scholarships with known ground truth. On every pipeline run, re-extract the same sources and compute
  precision/recall per field. Without this, "accuracy" is vibes, not a number.
  - Self-consistency / multi-sample. Run the extractor 3× with temperature 0.8 (which I already do for diversity) and take the majority-vote value per
  field. Disagreement flags the row for review.
  - URL liveness probe — a HEAD request to every scholarship link. If it's 404 or redirects to a generic page, mark needs_review. This catches staleness the
   LLM can't see.
  - Cross-source corroboration — when the same scholarship name appears from two different sources and key fields agree, boost confidence; when they
  disagree, queue for review.
  - Human-in-the-loop review queue — the /admin/imports route is the natural home. Route any row below a confidence threshold there; admin approves or edits
   before it goes live. Supabase makes this cheap because you already have RLS and service-key writes.
  - Observability — log failed[] reasons per run (the script already collects them in memory; it just doesn't persist them). A weekly rejection-reason
  breakdown tells you whether a source is drifting or the prompt needs updating.
  - last_seen_at column on scholarships — bump it every time a scholarship reappears in a scrape; scholarships not seen in N runs get marked stale and
  filtered out of the live list.
